# 05. パスキー4コマ漫画のネーム

フロント画面に「キャラが操作を見せる」演出を足すための、4コマ漫画のネーム（コマ割りとセリフの下書き）。動作検証のとき、いま画面で何が起きているかを絵と台詞で追えるようにするのが狙い。

絵は棒人間の2頭身で始める。差し替えやすいよう、キャラごとに「ポーズ名」だけを決めておき、画面側は状態名（`state`）でポーズを切り替える。

## 1. キャラクター

| キャラ | 役 | 見た目（棒人間・2頭身） | 画面上の対応 |
|---|---|---|---|
| ぱすた | ユーザー | 丸い頭が体の半分。体は1本線、手足は短い線 | 操作している人 |
| キーこ | 認証器（スマホ・セキュリティキー） | 頭に鍵のかたちの髪飾り。胸の金庫に秘密鍵を持つ | `navigator.credentials.*` の向こう側 |
| サバ蔵 | RPサーバー | 四角い頭。ノートに challenge を書く | `/api/*` |
| ニセ太 | 攻撃者（第4話のみ） | ぱすたと同じ形で、目が線になっている | Cookie を盗んだ人 |

```
 ぱすた         キーこ          サバ蔵          ニセ太
  ___            ___            _____            ___
 (・・)         (・・)🔑       [ ・ ・ ]         (－－)
  /|\            /|\            /|\              /|\
  / \            / \            / \              / \
```

ポーズ名: `idle`（立つ）/ `think`（腕組み）/ `ok`（両手を上げる）/ `ng`（×のポーズ）/ `scan`（指をかざす）/ `run`（走る）。

## 2. 第1話「はじめてのパスキー」（登録、docs/01 §5.1）

| コマ | 絵 | セリフ・効果音 | state |
|---|---|---|---|
| 1 | ぱすたがサバ蔵の前で名札に名前を書く | ぱすた「test-user-1 です。口座を作りたいな」 | `register:input` |
| 2 | サバ蔵が乱数のメモ（challenge）を渡す。メモは5分で燃える砂時計付き | サバ蔵「この数字に署名してきて。使えるのは1回だけだよ」 | `register:options` |
| 3 | キーこが胸の金庫の前で鍵を1本作る。ぱすたが指をかざす | キーこ「本人確認してね」ぱすた「ピッ（指紋）」 | `register:authenticator` |
| 4 | サバ蔵が公開鍵だけ受け取り、秘密鍵は金庫から出ていない | サバ蔵「公開鍵だけ預かるね」キーこ「秘密鍵は私の中から出ません」 | `register:done` |

オチ: 4コマ目で、サバ蔵の棚に「公開鍵」だけが並び、ぱすたの手元には何も残らない。パスワードを覚えなくてよい、を絵で見せる。

## 3. 第2話「名前を言わなくても入れる」（ログイン、docs/01 §5.2）

| コマ | 絵 | セリフ・効果音 | state |
|---|---|---|---|
| 1 | ぱすたが入力欄の前で手ぶらで立つ | ぱすた「ユーザー名、なんだっけ…」 | `login:idle` |
| 2 | サバ蔵が新しい challenge を差し出す | サバ蔵「この数字に署名してね」 | `login:options` |
| 3 | キーこが候補の鍵を並べて見せる。ぱすたが1本選んで指をかざす | キーこ「どの鍵にする？」ぱすた「これ！ ピッ」 | `login:authenticator` |
| 4 | サバ蔵が公開鍵で署名を確かめ、ぱすたに入館証を渡す | サバ蔵「署名OK。ぱすたさんだね」 | `login:done` |

オチ: 2コマ目のあと、ぱすたは1文字も入力していない。ユーザー名なしのログイン（`allowCredentials` が空）を見せる。

## 4. 第3話「送金の前にもう一度」（ステップアップ、docs/01 §5.3）

| コマ | 絵 | セリフ・効果音 | state |
|---|---|---|---|
| 1 | ログイン済みのぱすたが「送金先 / 金額」を書いて送る | ぱすた「test-user-2 に 100 送るよ」 | `transfer:submit` |
| 2 | サバ蔵が手のひらを前に出して止める | サバ蔵「待って。ここだけは、もう一度本人確認」（401 step_up_required） | `stepup:required` |
| 3 | キーこが「送金先・金額」のメモ付きの challenge に署名する | キーこ「この送金内容に、いま署名したよ」ぱすた「ピッ」 | `stepup:authenticator` |
| 4 | サバ蔵が承認券を1枚だけ受け取り、送金の窓口で使うと券が消える | サバ蔵「承認は1回きり。送金完了！」 | `transfer:done` |

オチ: 券は5分で期限切れ、使うと消える。もう一度送るなら、また指をかざす。

## 5. 第4話「盗まれたCookieは通れない」（攻撃の再現、docs/01 §6・§9）

| コマ | 絵 | セリフ・効果音 | state |
|---|---|---|---|
| 1 | ニセ太がぱすたの入館証（Cookie）をこっそり拾う | ニセ太「ふふ、これでぱすたになりすませる」 | `attack:stolen-cookie` |
| 2 | ニセ太が送金窓口に走り、入館証を見せる | ニセ太「100万、僕の口座へ！」 | `attack:transfer` |
| 3 | サバ蔵が手のひらで止める。ニセ太の後ろにキーこはいない | サバ蔵「入館証はOK。でも本人確認の署名がない」（401） | `attack:stepup-required` |
| 4 | ニセ太は鍵を持っておらず立ち尽くす。遠くでぱすたとキーこが無事に笑う | ニセ太「鍵が…ない…」キーこ「秘密鍵は私の中だけだよ」 | `attack:blocked` |

オチ: 盗めるのは Cookie までで、署名は盗めない。限界（画面の改ざんに騙されて承認するリスク）は docs/01 §9 に書き、ここでは触れない。

## 6. 実装（2026-11-25）

- 置き場所: `web/index.html` の `#manga`（タブ + 4コマの `<ol>`）。描画とアニメーションは `web/src/manga.ts`、スタイルは `web/src/style.css` 末尾。
- 状態の出どころ: `web/src/stage.ts` の `emitStage(state)` / `emitStageFailed()`。`register.ts` / `login.ts` / `stepup.ts` / `main.ts` が各段階で呼ぶだけで、認証処理の流れは変えていない。マンガ側は購読するだけ。
- 絵: SVG の棒人間（2頭身）と絵文字の小道具。ポーズは `idle` / `think` / `ok` / `ng` / `scan` / `run` / `stop`。
- 動き: いま進行中のコマだけが動く（体の揺れ、ジャンプ、ふせんが飛ぶ、鍵がぽんと出る、指をかざす、承認券が消える）。終わったコマは止まり、先のコマは灰色。失敗するとそのコマが揺れて赤くなる。`prefers-reduced-motion` では止める。
- 第4話: 実際の攻撃は動かさない紙芝居。タブを押すと、どの話も2.2秒ごとに自動再生する。本物の ceremony が始まると、再生は止まって実際の進行に追従する。
- 検証への効き方: アクティブなコマの `data-state` が現在の段階を示す。E2E は第3話の最終コマ（`transfer:done`）まで追従することを確認している。
- ログインの Conditional UI（オートフィル）は、ユーザーが選ぶまで進行が見えないため、選んだ時点で `login:done` に飛ぶ。
- 未決: 第4話を実際に動かすボタンにするか。動かす場合も docs/01 §6 の検証を外す操作は入れない。
